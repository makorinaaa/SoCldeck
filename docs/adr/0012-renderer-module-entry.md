# Renderer のモジュール入口と段階的移行

## 背景

HTMLのスクリプト順と `window.SocialDeck...` に依存していたため、依存先の追加漏れを実行時まで検出しにくかった。画面エントリには投稿メニュー、アプリ情報、Xリストダイアログの実装も残っていた。

## 決定

- `renderer.js` をES Modulesの単一入口とし、依存先を `import` で宣言する。
- 新規・今回抽出したモジュールは `.mjs` の名前付きエクスポートを使う。
- 既存のブラウザー形式モジュールは `legacy-runtime-modules.mjs` で読み込み、名前付きで再公開する。内部の従来形式と既存の単体テストは維持し、移行時に項目を取り除く。
- 投稿メニュー、アプリ情報・更新表示、Xリストダイアログは独立したファクトリーに移し、状態取得や操作を引数で渡す。
- ソース中の関数名を固定する構造テストを減らし、操作結果と失敗時の振る舞いを検証する。Electron E2Eは画面の未処理エラーでも失敗させる。

## 制約

既存モジュール内部のグローバル公開はまだ残る。全面移行ではなく、機能を変更するときに通常のES Modulesへ移せる境界を作る。互換モジュールに新規機能を追加しない。
