# X の自動化機能を同意制にする

## 背景

ネイティブ版の X カラム、SocialDeck の投稿画面からの X への投稿・同時投稿、通知センターの X 通知、X カラムの自動更新は、X の API を使わず、画面外の X ページの通信を DevTools Protocol で読み取ったり、X のページのボタンをスクリプトで押したりして動いている。

X の自動化ルールは、ウェブサイトのスクリプト操作など API 以外の自動化を禁止し、アカウントの永久凍結の可能性を明記している。利用規約も、公開されたインターフェース以外でのアクセスと、許可のないクロール・スクレイピングを禁止している。README の「API を直接呼ばない」という説明は凍結されにくさを示すだけで、規約への適合を意味しないという指摘を受けた。

## 決定

- これらの機能は、利用者が確認画面で「リスクを理解して使う」を選んだときだけ動かす。未選択と「使わない」では動かさない。
- 未選択の利用者には、X アカウントがあるときの起動時と、X アカウントを追加したときに確認画面を出す。「設定 → X の自動化機能」でいつでも変更できる。
- 同意の有無は人ごとの判断なので、ワークスペース（`socialdeck_v4`）とは別のキー `socialdeck_x_automation` に保存し、バックアップにも含めない。
- 判定は起動時に1回だけ行う。通信の読み取り（`xTimelineTap`）を作らないことで、ネイティブ版カラム・投稿ページの操作・通知の読み取りをまとめて止める。選択を変えたら、アプリを読み込み直して反映する。
- 使わない場合も、無印の X カラムで X のページを表示することはできる。ただし自動更新は予約せず、手動の更新はページの再読み込みだけにする（ボタンのスクリプト操作はしない）。
- README の冒頭と各機能の説明に、規約に反する可能性とアカウント制限のリスクを明記する。

## 制約

同意を得ても、規約に反する可能性は残る。これは利用者が判断できるようにするための対応で、規約への適合を保証するものではない。規約の範囲で同じ機能を提供するには、X の公式 API への移行か、自動化をやめてページの表示だけにするかを、別途判断する必要がある。
