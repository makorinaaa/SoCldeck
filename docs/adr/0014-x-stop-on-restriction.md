# X が制限・本人確認を求めたらアカウントの自動操作を止める

## 背景

X の自動化機能（ADR 0013）は、利用者のクリックで投稿やいいねを送るほか、自動更新や通知の取得のために X のページを操作している。X がアカウントの制限や本人確認を求めているのに操作を続けると、制限が重くなるおそれがある。これまでは、ログイン画面以外の制限を検知する仕組みがなかった。

## 決定

- 次のときに、そのアカウントの X の操作を止める。
  - X のページがアカウントのロック・本人確認の画面（`/account/access`）へ移った（メインプロセスがすべての X の WebView のページ移動を見る）
  - X の GraphQL が 429（回数制限）を返した（`x-page-diagnostics.js` が受け取る応答の状態コードを使う。`onCompleted` はセッションに1つしか登録できないため）
  - 投稿時に、X が回数制限・投稿の上限・自動化の疑い・本人確認・ロックを示す通知を出した（「返信が制限されています」のような投稿ごとの制限は含めない）
- 止めると、ネイティブ版カラムと画面外の X ページ（ホーム・投稿ページ・通知の取得）を閉じ、自動更新を予約しない。投稿・いいね・リポスト・削除・通知の取得も受け付けない。無印カラムで X のページを見ることはできる。
- 止めた状態は `socialdeck_x_paused` に保存し、再起動しても止めたままにする。利用者が X で確認して「再開」を押したときだけ解除し、アプリを読み込み直す。

## 制約

検知は、X が見せる画面や応答、通知の文言に頼っている。X が画面の場所や文言を変えると見逃すことがある。
