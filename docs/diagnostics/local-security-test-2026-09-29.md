# ローカル疑似サーバーでのセキュリティ検証

## 実施範囲

2026-09-29、`npm run test:security` で再実行できる8テストを追加し、全件成功。
疑似サーバーは `127.0.0.1` の空きポートのみで待ち受け、終了時に閉じる。
資格情報はテスト専用文字列で、実アカウント・実投稿は使わない。

API検証は実際の Gateway / AT Protocol Client を使用。fetch の注入ポイントで
固定の bsky.social 宛てをローカルHTTPへ置換し、通信・リダイレクト・タイムアウトを実行した。
本番の接続先許可リストは変更していない。TLS・証明書検証はこのテストの対象外。

Electron検証は専用Main、専用preload、一時プロファイルを使用し、外部ネットワークを遮断。
アプリの実際のHTML表示モジュールとIPC検証関数を読み込む。
悪意あるJSONをローカルサーバーから取得し、テストドライバー経由でDOM表示に渡した。
普段使用しているアプリやセッションには触れていない。

## 結果

| シナリオ | 確認結果 |
| --- | --- |
| 認証なし、他人のいいね・フォロー・リポストURIを指定 | 通信前に拒否、サーバー着信0件 |
| 他人のrepoDidを投稿パラメーターへ混入 | Vaultの本人DIDで送信、Cookie送信なし |
| 307で資格情報を別エンドポイントへ転送させる | 追従せず拒否、転送先への着信なし |
| 401を繰り返し返す | 更新1回・再試行1回で停止、無限再試行なし |
| トークン更新を遅延させ、その間にログアウト | 古い応答を拒否、Vaultは空のまま |
| 応答を返さない | 設定した期限で中断 |
| HTTP 200でHTMLを返す | 修正前は成功扱い、修正後はInvalidResponseで拒否 |
| HTML/属性/リンク注入、特権IPC、Nodeアクセス | 本文とウィジェットは文字として表示。別オリジンおよび同じローカルファイルを開いた別WebContentsからのIPCを拒否。rendererにrequire/processなし |

## 発見した不備

`parseResponse` が JSON 解析エラーを握りつぶして空オブジェクトを返していた。
200のエラーページでも投稿処理が成功扱いになり、利用者が未投稿を見落とす可能性がある。
権限突破ではなく応答検証・結果の完全性の不備。
JSON解析失敗、null、配列、プリミティブを明示的なエラーに変更した。
レスポンス本文はエラーメッセージに含めない。正当な空応答の扱いは維持する。

## 制限

この結果は上記の具体的な攻撃入力についてのもので、全面的な安全性の証明ではない。
X / Bluesky本体への侵入、配布インストーラーの全面監査、自動更新の改ざん試験、
FFmpegへの悪意あるメディア、全画面・全IPCの網羅的ファジングは実施していない。
Electronは実アプリの配布物ではなく検証用シェルであり、本番全体のE2Eとは区別する。
APIのネットワーク層はNode fetchであり、Electron net.fetch特有の挙動は対象外。

通常の単体テスト468件も成功。修正と検証コードはローカルにあり、公開版には未反映。
