# セキュリティ・性能の見直し（2026-10-06）

## セキュリティ

1. **リリース権限の分離・Action の固定**
   ビルドジョブ（依存パッケージのインストール・テストを実行）は `contents: read` に限定し、
   リリースへの書き込みは依存を実行しない公開ジョブだけに付けた。全 Action をコミット SHA で固定。
   自動更新は引き続き `latest.yml` のハッシュのみで検証する。コード署名と `publisherName` は証明書が必要なため未対応。
2. **X WebView の postMessage 中継を削除**
   任意オリジンの iframe から `x-reply` をホストへ転送できたが、受け手がなく未使用だった。
3. **配布版で `--dev` と `SOCIALDECK_FFMPEG_PATH` を無視**
4. **CSP の `img-src` / `media-src` から `'self'` を除外**
   file:// ページの `'self'` は他のローカルファイルにも一致する。アプリ自身のローカル画像はない。

## 性能

1. X WebView の UA は WebView ごとに一度設定し、実エンジンの版（`process.versions.chrome`）から作る。
   `navigator.userAgent` も一致する。Client Hints は X・Bluesky のホストだけに追加し、画像等の通信はフックしない。
2. 診断用 webRequest フックは X の GraphQL URL だけに限定。保存は実行中は非同期、終了時のみ同期。
3. Bluesky セッションは復号した値をメモリに保持し、API ごとのファイル読み込み・復号をやめた。
4. メイン画面は `backgroundThrottling: false` のため最小化しても `visibilitychange` が発火しない（Electron 43 で確認）。
   Main から最小化・復元を通知し、カラム更新・Bluesky 未読ポーリング・メモリ掃除を止める。デスクトップ通知は止めない。
5. 「新しいポスト」バナーの予備探索から投稿内のボタンを除外。
6. 広告ブロックのルールは 7 日を過ぎたら裏で取り直す。読めないキャッシュは再ダウンロード。

## 性能（追加）

1. Bluesky のアイコンは CDN の 128px 版（`avatar_thumbnail`）を使う。原寸は 1000px で、デコード後 1 枚約 4 MB。
2. X 通知の取得は、アカウントごとに 1 つの非表示通知ページを通知センター・30 秒ごとの確認・ネイティブ通知カラムで共有する。
   ホームの未読バッジが読めないアカウントでも、確認のたびにページ（プロセス）を作り直さず、開いたまま X の通知タブを押して更新する。
   タブで新しいデータが届かないアカウントは 2 回で諦め、従来のページ再読み込みに戻る。
   継続ページ（カーソル付き）の通知は破棄せず、最新の一覧に統合する。
3. Bluesky の投稿・通知にも `content-visibility:auto` を適用。新着を上に追加したときの読書位置は Electron 43 で変わらないことを確認。
4. X 通知（ネイティブ）カラムを追加。カラム内で X のページを動かさず、上記の共有通知ページのデータを描画する。

## 確認範囲

単体・Electron E2E・ローカルセキュリティテストで確認。UA・URL フィルター・可視状態は Electron 43 の検証用プロセスで確認した。
実アカウントでの X・Bluesky の表示とログインは未確認。
