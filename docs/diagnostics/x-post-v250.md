# v2.5.0 の X 投稿待機不具合

## 原因と再現

本文と添付画像が投稿欄へ反映され、送信ボタンが有効でも送信されない。
`x-composer-submit.mjs` が投稿欄全体の `role="progressbar"` を処理中と判定していたため、
常設の文字数ゲージで最大120秒待機し、最終的にタイムアウトしていた。

`node --test tests/x-composer-submit.test.js` に文字数ゲージが残るケースを追加すると、
修正前は「添付の完了または送信可能な状態を確認できませんでした」で失敗した。
添付領域だけの進捗検査に変えると成功。本文のみのケースも追加した。

## 修正

進捗・aria-busy の検査を attachments 領域内に限定する。
すべての添付の表示、投稿ボタンの有効化、エラー・投稿欄消失・タイムアウトの検査は維持する。
Electronの画面フィクスチャにも常設の文字数ゲージと一時的な添付進捗を同時に置き、
添付完了を待って一度だけ送信することを確認した。

## Bluesky の確認

Bluesky はゲスト画面の DOM を使わないため、この条件の影響は受けない。
実際の Delivery → Gateway → AT Protocol Client を通し、fetch のみを置換したテストで
本文・画像投稿の認証、本人の repo、レコード内容、正常完了を確認した。
既存の動画アップロード・処理待ちのテストに加え、画像アップロード失敗時の投稿抑止と
失敗後に画面が送信中から再試行へ戻るケースも確認した。

単体468件と対象Electron E2E 1件が成功。実サービスへのテスト投稿は行っていない。
ユーザー環境での修正適用後の確認は未実施。

## 再発防止

進捗バーはアップロード専用ではない。外部サイトの画面フィクスチャには、
文字数ゲージなど常設の状態表示と、タイムライン内の無関係な添付も含める。
